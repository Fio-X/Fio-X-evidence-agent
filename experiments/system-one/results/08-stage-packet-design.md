# Experiment 08 — Stage Packet Design

## Hypothesis

Research, design, and publish boundaries can exchange content-addressed references plus validation bindings instead of whole IR documents, while preserving the fields existing consumers and validators require.

## Commands / measurements

- Read-only inspection: `rg` over `src/`, `runtime/`, `scripts/`, and `schemas/` for IR consumers and required fields.
- Read-only fixture measurement: an inline Python measurement over `fixtures/migration/story-ir/*.json`; serialized projections used compact JSON (`separators=(',', ':')`). No repository files were generated by the measurement.
- Baseline: commit `7188f692fb8d849bc2b4fea02af64d0a3423d00e`, branch `exp/system-one-r1-08-stage-packet-design`.

## Observed values

The representative fixture contains 212,492 bytes across its six JSON IR documents. The largest item is `fact-graph.json` at 184,122 bytes.

| Boundary | Existing IR compared | Minimal measured packet | Estimated reduction |
|---|---:|---:|---:|
| Research → Design | 194,040 B (`fact-graph`, `claim-graph`, `evidence-ledger`, `story-graph`) | 5,143 B | 188,897 B / 97.3% |
| Design → Publish | 25,533 B (`story-graph`, `claim-graph`, `infographic-spec`, grammar selection) | 3,745 B | 21,788 B / 85.3% |
| Both projections | 212,492 B | 8,888 B | 203,604 B / 95.8% |

The research projection retained: `story_id`; source and derived-artifact refs plus SHA-256 hashes; IR hashes; claim IDs/kinds/fact and evidence IDs/support status; story-node IDs and bindings; semantic guards; and calculation IDs/result hashes/replay status.

The design projection retained: story/claim/plan refs and hashes; reader-facing question/thesis; selected grammar and decision log; module IDs/types, asset refs, story-node IDs, claim sets, roles/priorities; and reason codes.

Repository evidence supports these fields: schemas require story/claim/plan refs, module `story_node_ids`, publication evidence bindings with `result_hash`, and grammar `reason_codes`/`decision_log`; validators inspect claim source/computation refs, computation result hashes, visualization manifest refs, and lint-to-computation hash equality.

## Limitations

- This is one migration-story fixture, not a distribution across investigations.
- The byte estimate is a projection estimate, not an implemented transport benchmark.
- Hashes prove identity but do not make referenced artifacts available; the runtime would need bounded ref resolution and fail-closed missing/mismatch handling.
- The projection intentionally omits prose and full fact rows, so semantic equivalence and validator compatibility need a round-2 implementation test.
